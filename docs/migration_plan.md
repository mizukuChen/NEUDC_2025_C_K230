# 移植与验收计划

## 完成定义

K230 版本需要覆盖树莓派当前主线的完整功能：

- A4 黑框定位、透视校正和距离估计；
- 圆形、等边三角形、单个及多个分离正方形；
- 实心重叠多正方形和低分辨率/多帧识别；
- 普通识别与指定数字识别；
- 倾斜物面检测；
- 静默预识别缓存；
- 正式 800×480 触摸界面及独立相机诊断能力。

准确率优先。静态目标从触发测量到稳定输出的目标时间为 5 秒以内；某一复杂场景若无法
同时满足准确率与时间，必须记录耗时和降级原因，不能用错误结果换取速度。

## 阶段与出口条件

### Phase 0：固件能力探针

- 输出真实固件、Sensor、可用模块、内存区域和显示/触摸信息；
- 验证 GC2093 的 1920×1080 采集，以及至少一个独立算法通道；
- 验证 RGB888、灰度、图像引用和释放行为；
- 探测 `image`、`cv_lite`、`ulab.numpy`、LVGL、nncase runtime 的实际 API；
- 对二值化、形态学、线段、轮廓、透视、PnP 等原语做耗时和输出测试；
- 连续运行 30 分钟，无持续内存增长和媒体缓冲泄漏。

出口产物：`runtime_probe.json`、原始样帧、API 能力表和基准耗时表。

### Phase 1：跨平台结果契约与黄金数据

- 从树莓派参考实现导出普通、数字、重叠、倾斜场景的结果 JSON；
- 固化原图、A4 角点、校正图、目标列表和最终测量值；
- 定义数值容差，不要求两平台中间图逐像素相同；
- 每次更换固件、相机 profile 或 C++ 扩展都重跑回归集。

### Phase 2：相机诊断闭环

- 完成 Sensor/Display/TOUCH 生命周期；
- 支持预览、保存原图、ROI、曝光/增益、帧率与内存显示；
- 确定自动曝光预热后锁定或全手动曝光策略；
- 采集普通内参和距离标定数据并在主机端求解；
- 建立断开、超时和启动失败的可恢复错误路径。

### Phase 3：基础测量闭环

依次实现 A4 定位、透视校正、单正方形、圆形、三角形、距离和倾斜姿态，再实现多个
分离正方形。每项必须先通过离线黄金样本，再进入实时相机测试。

### Phase 4：数字与重叠识别

- 数字识别先比较两条路线：复现 HOG+线性 SVM，以及训练小型 KPU 分类器；
- 以现场准确率、最差样本和总延迟选择实现，不强制保留原模型；
- 重叠正方形最后移植，优先复用算法约束与真值；
- MicroPython 原语不能稳定满足 5 秒目标时，将候选生成、线支持、距离变换等热点下沉
  到 C/C++ 扩展，而不是整体重写应用层。

### Phase 5：状态机、静默识别和正式 UI

- 第一版使用单线程状态机；
- 基础测量稳定后增加场景签名、几何缓存和数字缓存；
- 触摸按钮测量优先于后台预识别；
- 界面固定按 800×480 设计，不照搬树莓派 1024×600 控件布局；
- 所有异常都必须恢复到可再次测量的状态。

### Phase 6：整机验收

- 覆盖距离、角度、光照、目标类型和复杂度矩阵；
- 每个关键场景至少重复测量 30 次；
- 连续运行、重复启动、掉电恢复、存储空间不足和相机错误测试；
- 记录平均、P95、最坏耗时以及尺寸/距离误差；
- 锁定固件镜像、K230 commit、主仓库 submodule commit 和相机 profile。

## 分辨率策略

不直接把“高分辨率”解释为所有算法始终处理 1920×1080 RGB：

1. GC2093 首选以 1920×1080 采集；
2. A4 粗定位可用硬件缩放后的较小灰度通道；
3. 候选四角在高分辨率灰度图中精修；
4. 只将 A4 区域透视到工作图；
5. 对重叠线段和小数字保留足够分辨率，实际工作图尺寸由 Phase 0/黄金集共同决定；
6. 若硬件输出要求 16 像素对齐，分别验证软件 420×594 与对齐工作图，按准确率选择。

## 风险排序

1. 重叠正方形的线段重建和多帧融合；
2. MicroPython 图像内存所有权及媒体缓冲泄漏；
3. 固件 v1.8 与公开文档/API 示例的版本差异；
4. 1920×1080 全帧处理导致延迟或不必要的数据复制；
5. GC2093 自动曝光变化引起阈值漂移；
6. HOG 特征实现差异导致原 SVM 权重不可直接复用；
7. LVGL、Display 和图像缓冲同时工作时的内存压力。

## 版本与变更规则

- 一个提交只完成一个可验证的纵向切片；
- 平台、视觉、UI 之间通过小接口交互，不跨层访问实现细节；
- 更改结果语义必须同时更新黄金数据与树莓派参考端；
- 引入 C/C++ 扩展前先保存 Python 基线和性能证据；
- 比赛/验收前冻结固件、配置、模型和 submodule commit。
