# K230 软件架构

## 原则

1. K230 是独立运行时实现，不从树莓派源码中导入 `cv2`、完整 NumPy、Tkinter、
   V4L2、`fcntl` 或 CPython 线程代码。
2. 优先复用结果契约、物理常量、模型参数、标定流程、靶图、测试图和算法规则；
   只有通过双运行时测试的纯 Python 才做源码级复用。
3. 平台 API 只能出现在 `nuedc_k230/platform`，视觉算法不能直接初始化 Sensor、
   Display 或 TOUCH。
4. C/C++ 扩展隐藏在与 Python 实现相同的接口后面，应用和 UI 不感知实现方式。
5. 主循环中的图像所有权必须明确，所有大对象都要有确定的释放点。

## 依赖方向

```text
platform ──┐
           ├──> app ──> ui ──> main.py
vision ────┘
```

- `platform`：提供相机帧、显示表面、触摸事件、时间、存储和内存统计；
- `vision`：接收约定格式的帧，返回普通 Python 测量结果；
- `app`：管理采集、稳定场景判定、缓存、测量模式、错误恢复和超时；
- `ui`：只消费状态与结果，不直接调用视觉算法。

## 图像管线

```text
GC2093
├── 显示通道 ──> Display/LVGL 预览
└── 算法通道 ──> ROI/灰度 ──> A4 定位 ──> 透视校正
                                      ├── 轮廓几何
                                      ├── 重叠正方形
                                      ├── 数字识别
                                      └── 距离与物面姿态
```

1920×1080 是首选采集分辨率，但不是所有阶段都必须处理完整彩色帧。A4 定位可在降采样
图上产生候选角点，再回到高分辨率灰度图精修；透视校正后只保留测量所需的 A4 工作图。
这能保留复杂线条的空间信息，同时控制 MicroPython 堆、MMZ/VB 缓冲和处理时间。

## 数据边界

应用层结果至少包含：

```text
status, error_code, mode, elapsed_ms,
distance_mm, plane_axis_angle_deg,
targets[{shape, x_mm, center_mm, angle_deg, confidence, digit}],
selected_target
```

树莓派参考实现和 K230 实现使用同一语义，但不要求内部类、数组类型或图像对象相同。

## 相机 profile

相机配置必须由以下字段共同标识：开发板、固件、Sensor、镜头、采集分辨率、像素格式、
镜像/翻转。更改其中任一项都不得静默复用旧内参或距离修正。

当前不处理鱼眼和定焦问题，但仍必须完成 GC2093 的普通内参、A4 PnP 距离修正、曝光策略
与现场 ROI 标定。
